# M5-E execution safeguards

Existing host remains GET-only, starts no signer or payout worker, verifies RPC network identity and retains restricted active-Testnet allowlists/read-only PostgreSQL behavior. Existing configuration tests reject inconsistent networks and protected contract identities. No real environment files, credentials, campaign state, contract settings or reviewed persistence code were changed.

A dormant local policy validator checks the isolated Testnet contract/token, canonical atomic limits, max payout <=100000 units, campaign exposure <=1000000 units, pending <=4, one attempt, bounded duration, emergency-stop type and independent operator/approver/executor identities. Its assessment ALWAYS returns executionEnabled:false; supplied ownership booleans cannot enable anything. This supplements future on-chain authorization and is not a new execution route. On-chain budget/reserve and native role/attempt/expiry/revocation/idempotency remain authoritative.

Pre-deployment checklist: pin source revision/WASM and compare current deployed code hash; verify owner and upgrade-key custody without exporting keys; snapshot pause/token/campaign/role configuration, independent approver/executor and verified recipient; check NEAR gas/storage headroom and USDC custody; verify migrations, bounded RPC configuration, authenticated read API and workers disabled. Record proposed payout/exposure caps, emergency-stop owner and evidence retention. Prepare migration rehearsal, in-flight callback compatibility and rollback limitations: older bytecode rollback can reintroduce bypasses and cannot undo token delivery. Every deployment, configuration write, pause action or payout still requires separate approval. No deployment readiness is inferred from a healthy process.
